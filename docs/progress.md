- 2026-09-26 (Phase A audit): nflreadpy's own cache is **off**. The per-season Parquet files under `data/raw` are the single cache. This deviates from spec 4.1 ("enable nflreadpy's cache") on purpose: nflreadpy's 24 h cache silently defeated the 12 h current-season refresh and `--force`, and doubled disk use (see `docs/assumptions.md` §10).
- 2026-09-26: the ingestion layer stays dtype-agnostic (raw cache and snapshots keep upstream dtypes, which is how drift is detected); the warehouse (B1) casts join keys. The list of known cross-season dtype drift is in `docs/assumptions.md` §10.
- 2026-09-26 (B1): the weekly as-of is **calendar-anchored**: the first Tuesday 14:00 UTC after the Eastern date of the week's *first* kickoff (spec 6.1 wording), not "the Tuesday after the last game". In five weeks a game was moved to Tuesday/Wednesday (2010 W16, 2020 W5/W12/W13, 2021 W15); a last-game rule would have put that week's as-of after the next week's kickoff. Those games are flagged (`dim_week.is_split_week`) and become available at the next week's as-of. The build asserts every as-of precedes the next week's first kickoff.
- 2026-09-26 (B1): every team column in the warehouse uses today's abbreviation (OAK→LV, SD→LAC, STL→LA, LAR→LA); the original is kept in `*_raw` columns. Schedules, snap counts, injuries and old depth charts use the abbreviation of the day, play-by-play does not, so joins broke for 1999–2019 without this.
- 2026-09-27 (B2): every availability rule errs LATE when unsure (a late estimate loses a little information; an early one leaks). Game data counts as public 6 h after the estimated game end, final scores 3 h after it; injuries use the report stamp (2010–2024, shifted +9 h for 2010–2020 whose stamps are not true UTC) or the team's kickoff; today's-snapshot player fields (position, height, weight, status, team) are hidden from predictions. Listed schedule changes (Irma, COVID moves, snow games...) carry no typed-in dates: they count from their own kickoff unless a date comes with a source link.

- 2026-09-27 (B3): nflverse's `players` table is the most trusted id source (unique Pro Football Reference and ESPN ids), then weekly rosters, then DynastyProcess's `ff_playerids`; an id that the winning source gives to two players is left out and reported, never guessed. A usage check overrides the precedence only when the data proves the link wrong (a snap season outside the linked player's career). The generated `reports/ids/unmatched_ids.md` is gitignored (regenerate with `uv run twm ids`).
